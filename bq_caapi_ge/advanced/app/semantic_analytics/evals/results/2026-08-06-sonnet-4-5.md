# Sonnet 4.5 Baseline: 2026-08-06

This baseline evaluates the V2 semantic analytics workflow with these models:

- Semantic selector: `gemini-3.5-flash`
- SQL generator: `claude-sonnet-4-5`
- Result summarizer: `gemini-3.5-flash`

The run used the twelve cases in `thelook_narrow.evalset.json`, local evaluation
contracts, a 1 GB per-query billing cap, and exact thresholds for both custom
metrics. No CA baseline was included.

## Smoke Run

Both smoke cases passed semantic selection and exact BigQuery result matching:

| Case | Result |
|---|---:|
| `completed_orders_total` | 31,132 |
| `available_inventory_total` | 306,006 |

The initial Sonnet 5 attempt did not reach evaluation because the active project
had not enabled `claude-sonnet-5`. Sonnet 4.5 was already enabled and returned
successfully from the global endpoint.

## Selection Failures

| Case | Passed runs | Observed difference |
|---|---:|---|
| `top_users_by_revenue` | 0/3 | Selected `completed_revenue` plus `user_id` instead of `top_users_by_completed_revenue` plus `user_id`. |
| `completed_orders_by_country` | 0/3 | Added `users__orders`, which the runtime relationship closure injects automatically. |
| `completed_orders_in_us` | 2/3 | Added `users__orders` in run 1. |
| `aov_by_country` | 2/3 | Added `users__orders` in run 3. |

All eight strict selection failures still produced the exact gold query result.
The relationship differences are redundant selections rather than missing
grounding. The top-users difference exposes overlapping metric definitions: the
generic completed-revenue metric and specialized top-users metric can produce
the same grouped, ordered, limited result.

The gold oracle remains unchanged. Changing it after observing these runs would
hide selector minimality and contract-overlap issues instead of measuring them.
